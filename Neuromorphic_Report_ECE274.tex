% ABSTRACT
% ============================================================
\begin{abstract}
Spiking Neural Networks (SNNs) are well suited for edge inference because they process information through sparse, event-driven computation and can therefore be significantly more energy-efficient than conventional neural networks. In practice, however, these advantages are often limited by frequent memory accesses and redundant spike activity in digital hardware implementations. In this work, we present a hardware-software co-designed SNN inference architecture that addresses these inefficiencies through three lightweight mechanisms: a Dynamic Gatekeeper that suppresses unnecessary input spikes before SRAM access, adaptive thresholding that regulates hidden-layer activity, and an Early-Exit finite state machine (FSM) that terminates inference once the output becomes sufficiently confident. Using a LeNet-5-based SNN trained on the N-MNIST dataset, the proposed approach achieves 90.8\% classification accuracy while reducing average SRAM reads by 81.6\%, from 70,824 to 13,002 per inference. These results show that simple hardware-aware control logic can substantially improve the practical efficiency of SNN inference for edge applications.
\end{abstract}

% I. INTRODUCTION
% ============================================================
\section{Introduction}
The increasing deployment of intelligent sensing systems at the edge has created a strong need for low-power, low-latency local inference. Among the available approaches, Spiking Neural Networks (SNNs) have emerged as a promising alternative to conventional dense neural networks because they communicate using sparse, asynchronous binary events. This event-driven mode of computation makes SNNs especially attractive for always-on sensing and low-power embedded applications.

However, translating the theoretical efficiency of SNNs into practical digital hardware remains challenging. In typical CMOS-based implementations, the dominant energy cost is often not arithmetic itself, but memory movement. According to widely used 45\,nm CMOS energy estimates~\cite{horowitz2014energy}, a single 8-bit SRAM access consumes approximately 5~pJ, which is more than two orders of magnitude larger than the cost of an integer addition. As a result, excessive memory traffic can largely negate the sparsity advantages that make SNNs appealing in the first place.

Recent progress in neuromorphic computing has focused heavily on improving training quality and model accuracy, for example through surrogate-gradient learning~\cite{neftci2019surrogate} and refined temporal coding strategies~\cite{zenke2021remarkable}. While these methods have made SNNs more competitive algorithmically, they do not always translate into hardware-efficient execution. In particular, many studies report classification performance without explicitly addressing the hardware consequences of spike activity in terms of memory reads, switching activity, or execution time.

In this work, we take a hardware-first view of SNN inference. Rather than optimizing only for accuracy, we explicitly target the dominant source of digital energy consumption: memory access. Starting from a baseline convolutional SNN trained using surrogate gradients, we introduce three complementary architectural mechanisms:
\begin{itemize}
    \item \textbf{Dynamic Gatekeeper Filtering:} A combinational front-end stage that examines incoming spikes and suppresses spatially insignificant or temporally redundant events before they trigger SRAM reads.
    \item \textbf{Adaptive Activity Regulation:} A lightweight adaptive-threshold mechanism that limits excessive hidden-layer spiking using only simple add/subtract operations.
    \item \textbf{Confidence-Driven Inference Termination:} An integer-based early-exit finite state machine that halts temporal processing once the output layer has accumulated sufficient evidence for a confident prediction.
\end{itemize}

A key aspect of this work is that all three mechanisms are implemented consistently in both the algorithmic PyTorch model and corresponding hardware-oriented digital models. The PyTorch model is used for training, evaluation, and collection of hardware-proxy metrics, while the digital module abstractions reflect the same control logic intended for future hardware realization. In addition, hardware-proxy counters are embedded into the PyTorch forward pass so that the reported efficiency metrics correspond directly to the control behavior expected from the proposed hardware modules.

\section{Dataset and Preprocessing Pipeline}

\subsection{N-MNIST Event Stream}
N-MNIST is a neuromorphic version of the standard MNIST dataset, generated by recording static digit images with a Dynamic Vision Sensor (DVS) under controlled saccadic motion~\cite{orchard2015converting}. Each event is represented as a tuple $(x, y, p, t)$, where $(x,y)$ denotes pixel location, $p$ denotes event polarity (ON/OFF), and $t$ is the timestamp. The dataset contains 60,000 training samples and 10,000 test samples across 10 digit classes.

\subsection{Spatial Normalization}
The native sensor resolution of $34\times34$ pixels is center-cropped to $28\times28$ so that it matches the spatial assumptions of the LeNet-5-style convolutional backbone:
\begin{equation}
x' = x - 3, \quad y' = y - 3.
\end{equation}
Events that fall outside the retained region are discarded, since they primarily correspond to peripheral activity introduced by sensor motion.

\subsection{Temporal Binning}
To enable batched training and hardware-style stepwise execution, the continuous event stream is discretized into $T=20$ uniform temporal bins over the approximately 300~ms capture window:
\begin{equation}
b_i = \text{clip}\!\left(\left\lfloor \frac{t_i - t_{\min}}{t_{\max} - t_{\min}} \cdot T \right\rfloor, 0, T{-}1\right).
\end{equation}
Polarity is preserved, producing binary input tensors of shape $(T, 2, 28, 28)$. This format retains temporal structure while making the data compatible with both software simulation and synchronous digital execution.

\subsection{Leaky Integrate-and-Fire (LIF) Dynamics}
At timestep $t$, the membrane potential of neuron $j$ evolves according to
\begin{equation}
V_j(t) = \beta \cdot V_j(t{-}1) + X_j(t),
\label{eq:lif}
\end{equation}
where $\beta = 1 - 2^{-4} = 0.9375$ is a hardware-friendly leak factor and $X_j(t)$ denotes the synaptic input after batch normalization. A spike is generated according to the threshold rule
\begin{equation}
S_j(t) =
\begin{cases}
1, & V_j(t) \ge V_{th,j}(t) \\
0, & \text{otherwise.}
\end{cases}
\end{equation}
After spiking, the neuron undergoes soft reset:
\begin{equation}
V_j(t) \leftarrow V_j(t) - S_j(t) \cdot V_{th,j}(t),
\end{equation}
which preserves residual membrane charge and supports smoother temporal integration.

\subsection{Surrogate Gradient Training (STBP)}
Because the spike generation function is non-differentiable, training is performed using a fast-sigmoid surrogate derivative~\cite{neftci2019surrogate,zenke2021remarkable}:
\begin{equation}
\frac{\partial S}{\partial V} \approx \frac{1}{\left(1+\alpha|V-V_{th}|\right)^2},
\end{equation}
with $\alpha=2.0$. Optimization uses Adam with learning rate $10^{-3}$ and a cosine annealing schedule. To encourage sparse activity, we include an L1 spike regularization term:
\begin{equation}
\mathcal{L} = \mathcal{L}_{CE} + \lambda \sum_{t,\ell,j} S_j^{(\ell)}(t), \quad \lambda = 5 \times 10^{-4}.
\end{equation}

\section{Hardware-Oriented Optimizations}
The central contribution of this work is a set of control mechanisms that reduce unnecessary memory activity during SNN inference. In particular, we introduce an input-side \textbf{Dynamic Gatekeeper} and an output-side \textbf{Early-Exit FSM}, together with adaptive threshold regulation in intermediate layers.

\subsection{Dynamic Gatekeeping}
Event-based sensory data often contains both noise and temporal redundancy. If every input spike triggers a weight fetch, a large number of SRAM accesses may be spent on events that contribute little useful information. To reduce this overhead, we place a \textbf{Dynamic Gatekeeper} in front of the Conv1 SRAM banks so that each incoming spike is evaluated \emph{before} any memory access is issued. As shown in Fig.~\ref{fig:gatekeeper_circuit}, the gatekeeper combines two lightweight filtering mechanisms.

\begin{figure}[htbp]
\centerline{\includegraphics[width=0.98\linewidth]{circuit_dynamic_gatekeeper.png}}
\caption{Block diagram of the Dynamic Gatekeeper. It combines an Importance Monitor (spatial frequency) and a Burst Redundancy Filter (temporal redundancy) to drop spikes before they trigger SRAM read operations.}
\label{fig:gatekeeper_circuit}
\end{figure}

\subsubsection{Importance Monitor}
The first sub-module addresses spatial noise, which is common in event-based sensors due to dark current and thermal fluctuations. To filter this, the Importance Monitor tracks how often each specific input location becomes active. In hardware, this is realized as a dense array of 4-bit saturating counters, $I[c,y,x]$, with one dedicated counter for each of the $2 \times 28 \times 28$ possible input addresses. 

To approximate a leaky temporal accumulation without utilizing any arithmetic multipliers, the design employs a global decay mechanism. A central timer orchestrates a global logical right-shift (equivalent to a divide-by-2) across all 1568 counters simultaneously, once every $W{=}255$ clock cycles. When an incoming spike arrives, its corresponding counter is incremented. The event is granted passage (marked important) only if its counter value strictly exceeds a minimum threshold \textit{prior} to the increment:
\begin{equation}
I[\text{pre\_id}] \ge \theta_{\text{imp}},
\end{equation}
with $\theta_{\text{imp}}=1$. Physically, this means a pixel must generate at least two spikes within the decay window to be deemed a genuine structural feature. This elegantly and efficiently drops isolated background noise events that do not recur spatially. The corresponding circuit is shown in Fig.~\ref{fig:importance_monitor}.

\begin{figure}[htbp]
\centerline{\includegraphics[width=0.98\linewidth]{circuit_importance_monitor.png}}
\caption{Importance Monitor logic. It evaluates incoming spike frequencies against a periodic decay to drop spatially isolated noise.}
\label{fig:importance_monitor}
\end{figure}

\subsubsection{Burst Redundancy Filter}
The second sub-module suppresses temporal duplication. Physical event cameras frequently produce rapid, short bursts of repeated spikes from the exact same pixel when a strong, high-contrast edge crosses the sensor's field of view. While the first spike in this burst carries critical localized timing information, the immediate subsequent spikes from the identical address offer diminishing returns for the network's spatial feature extraction. However, without intervention, every single spike in the burst would redundantly trigger the exact same weight fetch from the Conv1 SRAM.

To intercept this, the Burst Redundancy Filter acts as a spatial caching mechanism constrained within a specific temporal window ($\Delta t$). It utilizes a 12-bit register to hold the address of the most recently processed spike (\texttt{last\_pre\_id}) alongside a 3-bit \texttt{repeat\_count} register. Crucially, these registers operate on a per-timestep basis; when the global execution clock advances to the next discrete temporal bin ($t \to t+1$), the \texttt{last\_pre\_id} is cleared to prevent suppressing genuine, newly-arriving events that happen to occur at the same location much later in time entirely. Within the same timestep window, a hardware equality comparator constantly checks the incoming spike address against \texttt{last\_pre\_id}. If identical spikes arrive consecutively beyond a strict threshold $K_{\max}=1$, the $Keep_{corr}$ signal is pulled low and the events are suppressed. This requires minimal silicon area---just a few registers and a comparator---but yields massive energy savings by masking out redundant memory access strobes caused by sensor threshold jitter. The logic is illustrated in Fig.~\ref{fig:burst_redundancy}.

\begin{figure}[htbp]
\centerline{\includegraphics[width=0.98\linewidth]{circuit_burst_redundancy.png}}
\caption{Burst Redundancy Filter logic. It prevents rapid re-triggering of memory fetches for consecutive spikes at the exact same spatial address.}
\label{fig:burst_redundancy}
\end{figure}

\subsubsection{Gate Decision}
The final gatekeeper output is given by
\begin{equation}
Gate = En_{sys} \land S_{in} \land \text{Keep}_{imp} \land \text{Keep}_{corr},
\end{equation}
and directly controls downstream activity:
\begin{equation}
En_{mem} = Gate, \quad En_{mac} = Gate.
\end{equation}
When $Gate=0$, the SRAM read-enable is not asserted and the MAC unit remains idle. This prevents unnecessary memory access and switching activity, leading directly to dynamic energy savings.

\subsection{Adaptive Threshold Regulation}
To reduce spike bursts in hidden layers, each neuron uses a threshold that adapts according to recent firing history:
\begin{equation}
V_{th,j}(t{+}1) = 
\begin{cases}
V_{th,j}(t) + \rho, & \text{if } S_j(t) = 1 \\
\max(V_{th,j}(t) - 1, V_{th}^{base}), & \text{otherwise}
\end{cases}
\end{equation}
Here, $\rho$ is an additive firing penalty. If a neuron spikes, its threshold increases, making subsequent firing less likely; otherwise, the threshold gradually decays back toward a baseline value. This mechanism is intentionally hardware-friendly and requires only simple additions, subtractions, and comparisons. Similarly, the membrane leak term $V \times 0.9375$ is implemented as
\begin{equation}
V - (V \gg 4),
\end{equation}
which avoids multiplier usage entirely.

\subsection{INT8 Weight Quantization}
To support compact storage and hardware-efficient computation, all network weights are quantized to 8-bit signed integers using symmetric quantization:
\begin{equation}
\hat{W} = \text{clamp}\!\left(\text{round}\left( \frac{127}{\max|W|} \cdot W \right), -127, 127 \right).
\end{equation}
The quantized values are exported as hexadecimal files using two's-complement representation and are loaded into the memory model during initialization.

\subsection{Confidence-Driven Early Exit FSM}
While the gatekeeper reduces unnecessary work at the input, further efficiency can be obtained by shortening inference in time. The idea of early termination in SNNs has been explored algorithmically in prior work such as SEENN~\cite{li2023seenn}, where the exit condition is based on confidence estimates derived from floating-point scores.

In contrast, our design maps the same high-level idea into lightweight digital control logic. A small \textbf{Early-Exit FSM} monitors the cumulative output spikes for each class:
\begin{equation}
C_k(t) = \sum_{\tau=0}^{t} S_k^{(out)}(\tau).
\end{equation}
Inference terminates once any class count exceeds a fixed integer threshold $\theta_{conf}$:
\begin{equation}
En_{sys}(t{+}1) =
\begin{cases}
0, & \text{if } \max_k C_k(t) \ge \theta_{conf} \\
1, & \text{otherwise.}
\end{cases}
\end{equation}
In our implementation, $\theta_{conf}=8$. Once this condition is met, the global enable signal is deasserted and propagated upstream, freezing the full pipeline including the gatekeeper, memory access, MAC, and LIF stages. This mechanism is implemented using only 10 integer accumulators and a comparator network, with no divisions, softmax operations, or floating-point arithmetic. The architecture is shown in Fig.~\ref{fig:early_exit_fsm}.

\centerline{\includegraphics[width=0.98\linewidth]{circuit_early_exit_fsm.png}}
\caption{Early-Exit FSM architecture showing the 10-class integer accumulator and confidence comparator that generates the global pipeline freeze signal.}
\label{fig:early_exit_fsm}
\end{figure}

\subsection{Module Summary}
All proposed hardware blocks were developed and validated through Python-based digital modeling of the intended control and dataflow behavior. Due to project time constraints, complete RTL simulation and waveform-level verification were not performed. As a result, the hardware results reported in this work should be interpreted as behaviorally validated, hardware-oriented models rather than fully RTL-verified implementations. The main components are:
\begin{itemize}
    \item \textbf{Dynamic Gatekeeper}: top-level gating logic combining importance and burst filters.
    \item \textbf{Importance Monitor}: saturating spatial activity counters with periodic decay.
    \item \textbf{Burst Redundancy Filter}: suppression of consecutive duplicate spikes.
    \item \textbf{Quantized SRAM}: INT8 weight-memory abstraction with gated read behavior and exported quantized parameters.
    \item \textbf{Sparse MAC}: spike-conditional accumulation, exploiting binary presynaptic activity to avoid general multipliers.
    \item \textbf{Adaptive LIF}: leaky integration, threshold comparison, reset, and threshold adaptation.
    \item \textbf{Early-Exit FSM}: class-wise output accumulation and confidence-based global shutdown.
    \item \textbf{Top-Level Integration}: end-to-end integration of all modules into the complete inference pipeline.
\end{itemize}

\subsection{Inter-Layer Connectivity and Ping-Pong Spike Buffers}
In a hardware setting, the transfer of spikes between layers (e.g., from Conv1 to Conv2) presents a routing challenge. To address this iteratively, the datapath maps naturally into a tile-based Network-on-Chip (NoC), effectively bypassing any centralized memory bottleneck. 

\begin{figure}[htbp]
\centerline{\includegraphics[width=\linewidth]{Hardware_Architecture/multi_tile_noc_diagram.png}}
\caption{System-level block diagram of the Multi-Tile Network-on-Chip (NoC) architecture. Multiple SNN tiles (each containing local SRAM, MAC, and LIF arrays) are interconnected via a central routing mesh. Ping-Pong Spike Buffers sit between the routing mesh and the tiles to broker asynchronous spike transfer between sequential execution timesteps.}
\label{fig:multi_tile_noc}
\end{figure}

As shown in the system layout in Fig.~\ref{fig:multi_tile_noc}, each tile encapsulates its local SRAM, a MAC unit, and LIF neurons. When a spike is generated, its address ID is explicitly stored in an inter-layer \textbf{Ping-Pong Spike Buffer}. Because biological-style spiking is profoundly sparse, this inter-layer buffer only needs to be a small 256-element FIFO queue per active bank. 

By employing a double-buffering (Ping-Pong) strategy, pipeline saturation is strictly avoided: during timestep $T$, Conv1 pushes sparse spike addresses into Buffer A. When the global execution clock advances to the next timestep ($T+1$), the control finite state machine swaps the active bank. Conv2 reads the spike addresses from Buffer A and uses them to index its local Conv2 SRAM bank, while Conv1 simultaneously begins writing the new batch of $T+1$ spikes into Buffer B. This asynchronous tile-to-tile routing allows maximum pipeline utilization rates.

% VI. EXPERIMENTAL SETUP

\section{Experimental Setup}

\subsection{Training Configuration}
Training is performed in PyTorch using Adam with learning rate $\text{lr}=10^{-3}$, cosine annealing with $T_{max}=30$, and 50\% dropout in the readout stage. The baseline model is trained for 30 epochs on the full N-MNIST training set. The sparse model is trained under the same conditions, but with gatekeeping, adaptive thresholding, and early-exit behavior active in the forward pass so that the learned model is exposed to the same constraints that appear during efficient inference.

\subsection{Hardware Metric Collection}
Hardware-proxy metrics are collected using forward hooks embedded in the PyTorch implementation. These include:
\begin{itemize}
    \item \textbf{SRAM reads}: each spike that survives gating triggers a weight fetch; internal spikes similarly generate reads in later layers.
    \item \textbf{Gatekeeper statistics}: total input spikes, kept spikes, and rejected spikes per sample.
    \item \textbf{Per-layer firing rates}: total spikes normalized by neuron count and timesteps used.
    \item \textbf{Early-exit timestep}: the first timestep at which output confidence crosses the specified threshold.
    \item \textbf{Cumulative SRAM reads over time}: tracked at each timestep for temporal profile analysis.
\end{itemize}

\subsection{Energy and Latency Estimation}
Since this work uses Python-based functional modeling rather than RTL simulation, synthesis, or post-layout power analysis, energy is estimated analytically using published CMOS costs from Horowitz~\cite{horowitz2014energy}:
\begin{equation}
E_{total} = \sum_{t=0}^{t^*} \left[ N_{reads}(t) \cdot E_{SRAM} + N_{MAC}(t) \cdot E_{MAC} \right],
\end{equation}
where $E_{SRAM}=5$~pJ and $E_{MAC}=0.2$~pJ are literature-based estimates for 45\,nm technology. These values are not measured from a hardware implementation and should therefore be interpreted as proxy estimates derived from operation counts. Latency is estimated as
\begin{equation}
L = t^* \times t_{cycle},
\end{equation}
with $t_{cycle}=10$~ns corresponding to an assumed 100~MHz clock. This reflects the number of executed timesteps under the proposed control model, not the synthesized critical-path delay of a physical design.

\subsection{Evaluation Protocol}
All reported results are computed over $N=500$ randomly selected test samples using a fixed random seed. The baseline and sparse models are evaluated on exactly the same sample set to ensure a fair comparison.

\subsection{Savings Decomposition}
The total 81.6\% SRAM read reduction can be interpreted as the combined effect of three complementary mechanisms:
\begin{enumerate}
    \item \textbf{Gatekeeper filtering (input-side):} 23.9\% of input spikes are removed before any memory access, producing an immediate reduction in Conv1 read activity.
    \item \textbf{Adaptive thresholding + L1 regularization (internal):} the overall firing rate decreases from 8.92\% to 3.56\%, substantially reducing downstream spike-triggered reads.
    \item \textbf{Early exit (temporal):} the average execution length decreases from 20 timesteps to 11.4, removing all computation and memory accesses in the skipped tail of the sequence.
\end{enumerate}
These effects compound rather than simply add, since lower early-layer activity also reduces later-layer reads, and early exit suppresses both input and internal processing in all skipped timesteps.

\section{Conclusion}
This work shows that hardware-aware control logic can significantly improve the practical efficiency of SNN inference beyond what is achieved through algorithmic sparsity alone. By combining input-side event filtering, adaptive hidden-layer activity regulation, and confidence-based temporal truncation, the proposed design reduces SRAM read traffic by 81.6\%, lowers estimated energy by 81.6\%, and improves average latency by $1.8\times$, while maintaining 90.8\% accuracy on N-MNIST.

The main contribution of this project is not a new neuron model or a new training rule, but a deployment-oriented inference strategy that directly links SNN behavior to measurable digital hardware costs. The complete digital hardware design, including the gatekeeper, memory abstraction, sparse MAC, adaptive LIF, and early-exit control logic, was developed and validated through Python-based behavioral modeling and is structured for future RTL implementation and synthesis.

There are several clear directions for future work. First, full RTL implementation and simulation, followed by FPGA synthesis and place-and-route, would provide more realistic measurements of area, power, and timing. Second, the gatekeeping idea could be extended to deeper layers to enable multi-stage filtering throughout the network. Third, the confidence threshold used for early exit could be learned or adapted dynamically rather than being fixed globally. Finally, evaluation on larger neuromorphic benchmarks such as DVS-CIFAR10 and N-Caltech101 would help determine how well these hardware-oriented gains scale to more challenging datasets.
